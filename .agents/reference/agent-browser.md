# agent-browser E2E mechanics (canonical)

Read this BEFORE any browser E2E against the demo (the pin/composer flows).
Extracted from SKILL.md §6 (v0.6.7 condense) — the full mechanics, unchanged.

`type`/`press` keyboard goes to the TOP document even with the iframe focused — dispatch `KeyboardEvent`s on the iframe's `document` via eval. Pin clicks: real mouse events (down/up); `mouse click` is invalid. Synthetic sidebar `.click()` does NOT navigate — use URL navigation or real pointer events. `frame <selector>` can succeed yet leave `eval` in the TOP doc — verify `document.location.href`, or reach the iframe from the manager: `document.getElementById('storybook-preview-iframe').contentDocument` (reads/dispatch/innerText OK). React inputs need the native-setter: `Object.getOwnPropertyDescriptor(win.HTMLTextAreaElement.prototype,'value').set.call(ta, txt)` + `new Event('input',{bubbles:true})` + `.click()` the button in the iframe doc. Manager-panel inputs are TOP-doc — `fill`/`Enter` work (panel reply = `<input>`). Synthetic React events race state — arm, WAIT, verify the cursor class, THEN click in a SEPARATE eval. The pin command is blocked ONLY by a composer holding a draft (spoken hint: "Submit or cancel the open comment first (Esc)"); a thread popup does NOT block it (the command closes the popup and arms). `elementFromPoint` in the click handler: overlays (open drawer, hover-box) at the target swallow the pin — close drawers before pinning. Armed check: no capture banner — the iframe body carries the armed cursor/hover-box class, NOT banner text. Assert pins by `.annota-pin/.annota-region` COUNT + raw `localStorage['annotakit:static:<scope>']` payload (pre/post-reload), never innerText.

# v0.6.9 session additions (E2E-verified)

- **eval scope PERSISTS between calls** — a `const x` from one eval breaks the next (`Identifier has already been declared`). Wrap every eval body in an IIFE: `(()=>{ ... })()`.
- **Shell quoting eats backticks** — template literals inside double-quoted shell args arrive mangled (`+el.textContent+` literal). Use string concatenation, never backticks, in eval bodies passed through bash.
- **`close` + immediate `open` can land on about:blank** — re-issue the open and re-verify `location.href` before driving the page.
- **The canvas can be SHORT** (~237px with the bottom dock open): `elementFromPoint` returns NULL outside the iframe viewport — for pin clicks pick elements whose rect center satisfies `0 < y < innerHeight` (iterate `#storybook-root *` and take the first in-viewport element with real size). Clicks at out-of-viewport coords silently do nothing (no composer).
- **Open the panel**: the bottom-dock tab is `[role=tab]` with text "Annotakit" — dispatch mousedown/up/click on it. Panel buttons (recall/view, delete) are React: dispatch real mouse events at their rect center. Finding a specific row: match `btn.parentElement.parentElement.textContent` (the row div) — do NOT walk more than ~3 levels up (the LIST container matches every row).
- **Freeze/recall E2E (gate 5b)**: open the portal surface FIRST (dispatch click on the trigger with clientX/Y — the story reads them for placement), WAIT a tick (React portal render is a microtask), THEN dispatch ⌥I as a KeyboardEvent on the IFRAME document (`{key:'i', code:'KeyI', altKey:true, bubbles:true}` — the freeze letter moved F→I in v0.6.10); assert `[data-annota-frozen]` + the portal clone INSIDE it. v0.6.14: the persistent `.annota-frozen-pill` is DELETED (user directive: no sticky elements on the DOM surface) — instead assert the TRANSIENT `.annota-capture-hint` carrying '❄ frozen —' (or '❄ recalling #N —' on a panel view/recall) IMMEDIATELY after entry (it renders a React commit later — re-check after a short sleep), and that it is GONE ~3s later while the frozen view stays. Esc chain: first Esc closes the thread card, the SECOND exits the frozen view (by design — surfaces close before the view).
